详细描述

XMPPConnection 接口提供了与 XMPP 服务器连接的接口，并实现了不同类型连接（例如 XMPPTCPConnection 或 XMPPBOSHConnection）使用的共享方法。 要创建与 XMPP 服务器的连接，简单的使用示例如下：

 // 创建与 XMPP 服务器的连接。
 let con: XMPPTCPConnection = XMPPTCPConnection("user","password","xmpptestserver")
 // 连接到服务器
 con.connect()
 // 大多数服务器要求您在执行其他任务之前登录。
 con.login("jsmith", "mypass")
 // 开始与 John Doe 的新对话并发送消息。
 let chatManager: ChatManager = ChatManager.getInstanceFor(con)
 chatManager.addIncomingListener(IncomingChatMessageListener() {
     public void newIncomingMessage(from: EntityBareJid, message: Message, chat: Chat) {
         // 打印我们收到的任何消息到标准输出。
         println("Received message: ${message}")
     }
 })
 let chat: Chat = chatManager.chatWith("jdoe@xmpptestserver")
 chat.send("Howdy!")
 // 从服务器断开连接
 con.disconnect()

请注意，XMPPConnection 接口故意不声明任何操作连接状态的方法，例如 connect()、disconnect()。 您应该使用最具体的连接类型，例如 XMPPTCPConnection 作为声明类型，并在不需要操作连接状态时使用 XMPPConnection 接口。

XMPPConnections 可以在连接之间重复使用。这意味着一个连接可以连接、断开然后再次连接。 XMPPConnection 的监听器将在连接之间保留。

传入 Stanza 监听器

您可以添加到连接的大多数回调（监听器、处理程序等）有三种不同的变体：

  • 异步 - 例如 addAsyncStanzaListener(StanzaListener, StanzaFilter)
  • 同步 - 例如 addSyncStanzaListener(StanzaListener, StanzaFilter)
  • 其他 - 例如 addStanzaListener(StanzaListener, StanzaFilter)

异步回调与连接的主事件循环解耦。因此，由 stanza B 触发的回调可能（看起来）在 stanza A 之前被调用， 尽管 stanza A 在 stanza B 之前到达。

同步回调是并发调用的，但确保同一个回调不会并发运行，并且按顺序执行。 也就是说，如果 stanza A 和 B 都触发了同一个回调，并且 A 在 B 之前到达，那么回调将首先使用 A 调用， 然后是 B。此外，这些回调不会在主循环中执行。然而，建议这些回调不要阻塞或仅短暂阻塞。

其他回调与连接的主事件循环同步运行，并在主循环中执行。 这意味着如果这样的回调阻塞，主事件循环也会阻塞，这很容易导致死锁。 因此，除非您知道自己在做什么，否则应避免使用这些回调。

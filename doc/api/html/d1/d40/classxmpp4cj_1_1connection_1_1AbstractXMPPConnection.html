详细描述

public abstract class AbstractXMPPConnection <: XMPPConnection & ClassIdentify

这个抽象类通常用作诸如TCP和BOSH等XMPP连接机制的超类。 它提供了用于连接状态管理的一系列方法，这些方法在连接的不同阶段发挥作用，具体如下：

  • connect()：用于建立连接的相关操作。
  • login()：处理登录相关的流程。
  • disconnect()：负责断开连接的操作。 需要注意的是，这些方法特意未由XMPPConnection接口提供。

注意： Xmpp文档的默认入口点是XMPPConnection。 如果您刚开始接触Xmpp，建议先查阅XMPPConnection相关内容，然后再回到此处深入了解本类的相关细节。

解析异常

在Xmpp的运行过程中，如果一个Xmpp解析器（也可称为提供者）抛出异常， 这些异常会被传递给ParsingExceptionCallback进行处理。 解析器抛出异常的常见原因是接收到了非法输入， 例如，在程序逻辑中只允许输入整数的情况下，却接收到了非数字字符串。 Xmpp的默认行为遵循< b >“默认严格失败”原则， 这意味着一旦出现解析异常，将会导致连接直接终止。 之所以选择这样的默认行为，是为了让用户能够意识到他们需要自行配置回调机制， 并妥善处理这些异常情况，以避免连接意外断开。 处理解析异常的方式可以很简单，比如使用一个不抛出异常的空操作回调。 采用这种回调方式时，当遇到有问题的流元素，会将其从流中移除， 此时Xmpp的表现就如同从未接收到那个有问题的元素一样。

如果解析异常是因为Xmpp接收到了非法输入而引发的， 那么请考虑将此情况告知源实体的作者，以便他们能够对输入数据进行检查和修正。 如果异常是由于Xmpp解析器自身存在漏洞而抛出的， 那么请考虑向Xmpp项目提交一个漏洞报告，帮助开发团队修复问题，提升软件质量。

管理解析异常回调

“默认严格失败”的行为是通过使用 xmpp4cj.parsing.ExceptionThrowingCallbackWithHint作为默认解析异常回调来实现的。 如果您希望改变这种默认行为，可以使用 setParsingExceptionCallback(ParsingExceptionCallback)方法来设置一个新的回调。 另外，还可以通过 xmpp4cj.XmppConfiguration#setDefaultParsingExceptionCallback(ParsingExceptionCallback)方法 来设置整个项目的默认回调。

◆ disconnect() [2/2]

public func disconnect ( unavailablePresence:  ?Presence) : Unit

关闭连接。向服务器发送自定义不可用状态，然后关闭流。 XMPPConnection仍然可以用于再次连接到服务器。 自定义不可用状态对于传达离线状态信息（如“度假”）很有用。 通常，只有状态节的状态文本设置了在线信息，但大多数XMPP服务器将提供完整的状态节以及设置的任何数据。

参数
unavailablePresence是关机期间要发送的可选状态节。
异常
NotConnectedException如果XMPP连接未连接。

public func login ( ) : Unit

使用服务器支持的最强SASL机制登录到服务器。 如果在身份验证过程的每一步中超过连接的默认节超时，而服务器没有响应，则将抛出Xmpp4cjException.NoResponseException。
